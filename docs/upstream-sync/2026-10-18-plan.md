## 执行顺序

每步完成并通过检查后再进入下一步。检查命令沿用 [2026-10-02 计划](2026-10-02-plan.md) 的完整组合；Windows 代码按 `docs/agents/windows-pack.md` 构建，不安装、不重启已装 Codex，不对运行中的 Codex 执行 CDP 页面重载。

0. **实机前置核验（只读）**：在当前 Windows Codex 上复测审计第 2、3 项的证据，即 fuse 状态，以及模型补丁对当前真实资源的匹配次数；同时确认账号额度不显示的原因。macOS 的 fuse 状态目前无法探测，记为未知。
1. **丙组**：五项小修复和应用图标。验收：锁测试在并行运行下稳定通过；设置入口测试覆盖 `aria-hidden` 场景。
2. **乙组**：vendor 三方合并 `99c14032` 和 `06c49c57` 的 vendor 部分，保留 `Page.enable` 与页面独有请求编号；随后移植 `cdp.rs`、`5e76f4f7`、`51f4d391`。验收：`cargo test -p codey-runtime-core`，包括 `cdp_bridge`。
3. **甲组**：移植 `06c49c57`、`294068c8`、`6a9fdf20`，删除主进程补丁路径；迁入本分叉独有的两个页面补丁；控制台「主进程注入」展示与 `startupInjectionMode` 随之调整。然后在新机制上适配审计第 3 项的模型锚点，用当前真实资源验证匹配结果。验收：Linux 与 Windows 检查通过，Windows 安装包实机确认补丁命中，需用户协助。
4. **审计第 1 项**：删除前改为确认服务端已真正释放会话；参考 `d8435f7d` 的原生管理器兼容。验收覆盖删除后继续发送、重新打开、多窗口，以及服务端仍持有会话。真实删除需单独授权。
5. **审计第 4、8 项**：更新兜底清单；Fast 与 Ultrafast 优先保留原生描述，不统一写 1.5 倍。分别验证原生目录完整、缺失和用户显式目录三条路径。
6. **审计第 5、6 项**：远程压缩和网页搜索读取 `capabilities` 声明；支持 `auth.command`，或明确报告暂不支持。不记录令牌，不回写配置。
7. **审计第 7 项**：验证内联 `[hooks]` 运行期覆盖能否替代写入 `hooks.json`。成立时减少用户目录写入，同步更新 ADR 0002 的例外说明。
8. **审计第 9 项**：先按第 0 步的诊断结果修复额度显示，再决定是否改为多组展示。
9. **三项重新评估**：各自先复现或确认原生能力，再决定保留范围；本计划不预设删除。

每步按 [fork-upstream.md](../agents/fork-upstream.md) 的半移植检查更新差异表、`INTERNAL_DEVELOPMENT.md` 和 README。

### 审计第 7 项前置验证（2026-10-18，已由我们确认）

方法：临时 `CODEX_HOME`，本机 `codex-cli 0.163.0` 的 `app-server` 经标准输入输出调用 `hooks/list` 与 `config/read`，不调用模型，不读写用户配置。

- 单条 `-c 'hooks={PreToolUse=[...],state={"/<session-flags>/config.toml:pre_tool_use:0:0"={trusted_hash="sha256:…"}}}'` 定义的 Hook 被载入，`source` 为 `sessionFlags`，`trustStatus` 为 `trusted`；同内容的哈希与 `hooks.json` 来源相同
- 用户 `hooks.json` 加用户配置信任项时，上述运行期覆盖不会替换用户的 Hook 或信任项，两者都为 `trusted`
- 现有缺陷：`-c` 的点号路径不识别引号。`-c 'hooks.state."/x/hooks.json:pre_tool_use:0:0".trusted_hash=…'` 被解析为键 `"/x/hooks`。Codey 当前按这种形式传 Hook 信任项（`codex_config.rs` 的 `hooks.state.{state_segment}.trusted_hash`），路径含点号时信任不生效，Hook 保持未信任并被跳过。只在 Linux CLI 上复现，Windows 桌面版待实机确认
- 结论：Hook 可改为单条内联运行期覆盖，不再写用户 `hooks.json`；ADR 0002 的 `hooks.json` 例外随之取消
