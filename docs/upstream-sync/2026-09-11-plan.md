# 同步到上游 v1.0.0 的计划

- 日期：2026-09-11
- 依据：[2026-09-11-digest.md](./2026-09-11-digest.md)
- 目标锚点：上游 `v1.0.0` = `40b1221`（不要接到 `upstream/master`）
- 本分叉起点：`d3cb766`（产品版本 0.10.8，Mantine，无内置路由）
- 状态：三期均已执行。一期与三期 vendor 落在 `master`（`1004002`..`364e84c`），二期与三期文档落在分支 `sync/heroui-v1`（`5220703`..`18cc07b`），尚未合并回 `master`。备份分支 `backup/master-20260911-205228`。

## 锁定的前提

这些已经写在 ADR 里，本计划不重新讨论，除非你明确要改 ADR。

| 约束 | 来源 | 同步时的动作 |
|---|---|---|
| 不恢复内置路由 | [ADR 0001](../adr/0001-remove-built-in-router.md) | 拒绝 `backend/src/local_router/**`；保持 `local_router_enabled` 默认 false 且加载时强制关闭 |
| 不写用户 `config.toml` | [ADR 0002](../adr/0002-user-config-is-read-only.md) | 不收上游任何写盘/自动修复会话 provider 的路径 |
| 按提交挑选，不整段 merge | [ADR 0003](../adr/0003-track-upstream-by-cherry-pick.md) | 本期不用 rebase 接到 v1.0.0 |
| `vendor/CodeyRuntime` 整目录替换、内部未调用代码不删 | ADR 0003 | vendor 单独替换，不在 backend 里手改 vendor |
| 关闭自动更新 | ADR 0003 后果 | 不收 `useAppUpdates`；保留 `tests/update-disabled.test.mjs` |

上次接到 v0.10.7 时冲突面过大，破例用了分段 rebase。v1.0.0 这一段又叠了两次 UI 换库，再 rebase 会同时复活路由、拆掉 Mantine、把 24 个分叉提交重放到 HeroUI 树上。代价高于按功能切片。

## 明确不做

- 不 rebase、不 merge 到 `v1.0.0` 或 `upstream/master`
- 不经过中间态 Ant Design（`a4c71a0`）
- 不收 PR #37 及之后的跨线路历史归一化（纯路由）
- 不把本分叉标签 `v0.10.8`（`dde98b1`）当成上游锚点；上游 v0.10.8 是 `933df25`
- 不 force-push `master`（若以后推送，只用 `--force-with-lease`，且需你另行确认）

## 策略

分三期，每期可独立停、独立验证、独立发布。一期做完，产品仍是「本分叉 0.10.8 + 上游运行期修补」。二期才换控制台外观。三期只收文档与 vendor。

```
一期  运行期修补（cherry-pick / 手工移植）     ← 建议先做
  │   仍是 Mantine；不碰 package.json UI 依赖
  ▼
二期  控制台迁到 v1.0.0 HeroUI                 ← 独立工程，需你点头
  │   以 v1 的 src/ 为基线，移植二开，不保留 Mantine
  ▼
三期  vendor 替换 + README / INTERNAL 对齐     ← 可与二期并行准备
```

若只想尽快吃到启动/提示词/Windows 修复：做完一期就可以停。

**目标：** 控制台外观与 v1.0.0 对齐，同时保住本分叉的产品差异。

**基线：** 从一期结束后的 HEAD 开分支 `sync/heroui-v1`。把 v1.0.0 的前端栈拷过来，再把二开迁进去。

## 风险与回滚

| 风险 | 处理 |
|---|---|
| `config.rs` / `launcher.rs` 手工移植漏 hunk | 每笔后 `cargo check`；对照 `git show <sha> -- <file>` |
| 额度后端接到芯片后出现双数据源 | 禁止同时启用 v1 侧栏额度注入 |
| 一期误 pick 带上 `local_router` | `git show --name-only` 预检；出现该目录立刻丢掉该提交 |
| 二期 HeroUI 与 overlay ShadowRoot 不兼容 | 先迁 `UiProvider` + overlay，再迁各卡片 |
| 想「一次接到 1.0」改用 rebase | 预演仍是约 70 个冲突路径；会复活路由。本计划不走这条 |

回滚：`git reset --hard backup/master-<时间戳>`。备份分支全程保留。

## 建议的开工方式

1. 先做一期。收益明确，不改外观，不改 ADR。
2. 二期单独开干，当作一次前端移植，不要和一期挤在同一次 rebase 里。
3. 三期的 vendor 可以在一期结束后随时做；README 等到二期外观定了再写，避免写两次。
