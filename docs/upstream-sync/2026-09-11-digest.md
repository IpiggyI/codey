## 建议

不要整段 rebase 到 v1.0.0，更不要接到 `upstream/master`。

原因：

1. 控制台 UI 在这一段里换了两次（Mantine → Ant Design → HeroUI）。不能和本分叉的 Mantine 做三路合并，只能整栈收上游再把二开迁过去。
2. 上游 v1.0.0 仍带完整 `local_router`（约 30 个路径），新建配置默认打开。本分叉已删除该树（`a3fe2d7`）。rebase 重放删除提交时，这 20 多个已改过的路由文件会冲突；选上游就会把路由加回来。
3. 本分叉的输入栏额度芯片（`public/composer-usage.js`）上游没有；上游额度走 `renderer-inject.js` + `QuotaEstimateDialog`。同一条产品线，两边改的不是同一文件。
4. 上游 README 写了客户端更新；本分叉明确不自动更新。

若之后仍要取上游能力，先定架构再动手：

1. **继续去掉内置路由**（与 ADR 0001 一致）：拒绝 `backend/src/local_router/**` 和任何恢复 `RequestLogDialog` 的路径；可手工摘不依赖路由的修复（提示词 reasoning、`1f19eff` 里握手/代理的非路由段、额度估算后端、Windows 包切换）。
2. **改收上游路由**：等于撤销 ADR 0001，还要处理 `codey_router_session_migrate` 和模型目录外置。
3. **UI**：一旦决定同步控制台，以 v1.0.0 的 HeroUI 为基线，把只读线路、composer 芯片、禁用更新迁过去，不要保留 Mantine。

分段检查点（若以后要同步）：上游 `933df25`（v0.10.8，仍是 Ant Design）→ `25a7a5a`（v0.10.9，HeroUI 已进入）→ `40b1221`（v1.0.0）。
