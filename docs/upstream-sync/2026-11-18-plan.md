# 上游 v1.5.5 至 v1.6.3 同步计划

- 日期：2026-11-18
- 对照范围：上游 `2e9f08b8`（`v1.5.5`）到 `v1.6.3`（`9316ed47`，即 2026-11-18 的 `upstream/master`），共 60 个提交；`v1.5.6` = `bbe11607`，`v1.6.0` = `629ec692`，`v1.6.1` = `2bb3967c`，`v1.6.2` = `f325eddb`
- 依据：[同步规则](../agents/fork-upstream.md#同步规则)。上游功能默认同步
- 前一轮：[2026-11-10-plan.md](2026-11-10-plan.md)

## 起因与现状

用户 2026-11-18 要求同步到上游 `v1.6.3`。本机 Codex 商店包为 `26.1111.2228.0`。

- 逐个对本分叉 `b40102ee` 试 cherry-pick：8 个提交可直接应用，52 个冲突。冲突来自本分叉删除的路由、请求日志、在线更新、Codey 插件，以及本分叉保留单文件而上游已拆分的模块。按 [ADR 0003](../adr/0003-track-upstream-by-cherry-pick.md) 逐主题移植。
- 对 `26.1111.2228.0` 安装包离线检索：`getForkCapabilities` 与 `execution-config-loading`（`c87e86a1` 的目标）、`checkout-webview-presentation-changed`（`5cf63984` 的目标）、`submitDisabledReasons` 与 `reserve-limit`（`0144c61d` 的目标）都存在；`forcePricingRefreshInBackground` 已不存在。
- 对 `26.1111.2228.0` 安装包的 10204 个脚本与样式表离线执行三版补丁入口（不关宠物）：

  | 补丁版本 | 改写文件 | 失配记录 | 重复执行仍改写 |
  |---|---|---|---|
  | `master`（`b40102ee`） | 35 | 43 条 / 8 项：模型白名单 5、模型可见性 5、第三方 Ultra 思考 16、服务档位请求模型校验 6、服务档位权限状态 8、额度购买页预热 1、Fast 模型触发可用性 1、app-server 模型结果改写 1 | 1 |
  | `master` 加未提交改动 | 36 | 42 条 / 7 项（额度购买页预热不再失配） | 1 |
  | 上游 `9316ed47` | 42 | 0 | 0 |

  即已发布的 `v1.4.3` 在 Codex 26.1111 上有 8 项页面补丁失效。上游同名项在 26.1111 上全部匹配；服务档位请求模型校验、Fast 模型触发可用性是本分叉独有项，须自行适配。
- 主工作目录有未提交改动：`renderer_asset_patch.js` 与对应测试适配 Codex 26.1106 合并结账组件的预热，`Cargo.toml` 加 `[profile.dev] debug = 0`。与 `5cf63984`（26.1111 个人结账页）针对同一组件的不同版本，正则不重叠。

## 决定

用户 2026-11-18 决定：

- 主工作目录的未提交改动（26.1106 结账预热及测试、`[profile.dev] debug = 0`）作为独立提交并入同步分支，RP 在其上进行。
- 控制台改版照收（`8864d1a9`、`719322f0`、`64339a32`、`893f0f4f`、`629ec692` 的样式部分）：引入上游的 `--codey-*` 主题变量、浅色白底扁平样式与石墨色深色主题，把本分叉现有页面改成上游的视觉。本分叉没有的标记（线路、Codey 插件、请求日志、用量分析）不引入。
- `d6bae126` 的账号用量卡片改版照收（11-11 验收过的进度环改为横向进度条）。
- 授权创建本地分支 `sync/upstream-9316ed47` 与工作目录，每份合同验收后本地提交，不推送。

主会话按同步规则自行确定、在此记录：

- vendor 整目录替换到 `9316ed47`，保留本分叉三处改动（`model-catalog-metadata.json`、`bridge.rs`、`cdp.rs`）。上游 `3e6902a5` 删除了 `codey-runtime-data`，本分叉 `session_delete.rs` 仍调用其 `delete_local_from_paths`（以及 `codey_runtime_core::models` 的 `DeleteResult`、`DeleteStatus`、`SessionRef`）。把这部分代码移入 `backend/src/session_delete/` 作为本分叉自有代码，vendor 不再保留该 crate，根 `Cargo.toml` 去掉成员与 `[profile.dev.package.codey-runtime-data]`。`cargo tree -e features -i serde_json` 显示工作区内只有 `codey-runtime-data` 打开 `serde_json` 的 `preserve_order`；删除后 backend 的 `serde_json` 自己声明 `preserve_order`，否则全工作区 JSON 键序改变。新 vendor 清单用到的工作区依赖本分叉根清单都有；`tokio-tungstenite` 保留本分叉的 TLS 特性。
- `renderer_asset_patch.rs` 按上游 `7d1acf63` 拆出 `anchors.rs`、`cache.rs`、`tests.rs`，让 `40d76183`、`6d20cd63` 等后续改动落在同样的位置。本分叉独有的逐项覆盖（`rendererPatchItems`、`AssetScan.items`、`missing_items`、失配上报）保留，不换成上游的 `PatchAnchorMatcher` 组合规则；本分叉的 `anchors.rs` 承载逐项定义，与上游同名文件内容不同，下次同步不能按上游原文替换。上游新增的性能补丁项改写为本分叉的逐项定义。
- `d6bae126` 的账号用量卡片改版照收：只有周额度窗口时的边框进度环改为横向进度条加大号百分比，带入上游字体与套餐标签样式。进度环来自上游此前的版本（上一轮完整移植），不是本分叉独有设计。
- 会话统计条：`0b2c51cd`、`9072fb67`、`41290046` 的机制部分照收（统计条固定挂在 `body` 上按输入框位置定位、切换会话不闪烁、按输入区宽度分三档精简），文字按本分叉现有文案（`N 轮 · N 步`、`X tok`、`缓存命中`）改写，不引入上游改版的文案与环形缓存标记。
- `b023f157` 只收不依赖路由的部分：查询非当前账号的额度前，令牌将过期则先刷新，刷新被明确拒绝（如 `invalid_grant` 或 401）时标记账号失效，网络失败不标记。当前账号按 `auth.json` 中的账号标识判定，不由 Codey 刷新，避免与 Codex 轮换同一个刷新令牌。每个账号一把刷新锁。

待用户决定：见「待决定」。
