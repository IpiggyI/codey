# 移除内置路由，请求由 Codex 按用户配置直接发出

上游 v0.9.0 把官方账号与第三方 provider 统一接入一个本机代理，代价是必须把 `codey_router` 写进用户的 `config.toml`。本分叉移除该代理及其线路管理：Codex 按用户自己写的 `[model_providers.*]` 直接发请求，Codey 只做运行期增强。

## 放弃的能力

同一线程内跨 provider 切换模型。替代做法是新开会话并交接进度——跨 provider 复用线程会作废 prompt cache 并触发上下文重新编码，代价通常高于新开会话。

## 考虑过的其他做法

- **保留路由，只停止写盘**：不成立。Codex 重开旧会话时要从磁盘解析该线程的 `model_provider`，路由必须在盘上留下 provider 表。
- **保留路由但默认关闭**：留下一万三千行永不执行的代码，与移除的目的相悖。上游后来加的 `local_router_enabled` 缺省必须为关闭；加载和保存 Codey 配置时若磁盘上仍为 true，按关闭处理。这不是“保留路由”，只是清掉同步残留的开关。
- **CC-Switch 兼容模式（默认关闭、显式启用）**：2026-08-05 曾按这个方向规划过一次二开，后因上游采纳建议并调整实现而作废。它不构成对本决策的约束，也不应再被当作有效规划引用。
