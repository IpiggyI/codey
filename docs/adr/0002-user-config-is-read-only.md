# 用户配置只读，运行期配置只走命令行覆盖

`~/.codex/config.toml` 由用户所有，Codey 不写入、不迁移、不重写，也不做"自动修复"。本次运行需要的配置一律通过 `-c key=value` 传给单次 Codex 进程；主进程补丁把同一批覆盖打进 `NODE_OPTIONS=--require` 脚本，同样不落盘。

唯一例外是运行期产物：Codex 不接受用命令行注入钩子，因此 `hooks.json` 仍需落盘，Codey 写入前备份、退出时恢复。

这条约束由三层验证守护，缺一不可：完整启动退出后 `config.toml` 字节级不变，证明最终状态；把 `config.toml` 设为只读权限后完整启停仍然成功，证明运行期从未写入；以及对启动、启动失败清理、重启、退出、旧租约恢复五条生产路径的写入调用审计。只有第一层会漏掉"先写入再恢复"的实现。

## 后果

放弃上游的 `codey_router` 恢复桩。v0.9.x 期间创建、`model_provider` 被标记为 `codey_router` 的旧会话，需要一次显式迁移——改写会话库与 rollout 记录，不碰用户配置。控制台提供该入口；启动时不再自动改写会话归属，这些旧会话在迁移前不能当普通会话继续使用。
