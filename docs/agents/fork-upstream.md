# 本分叉与上游的当前差异

对照上游、挑选、跳过或改写上游提交时，在同一次改动内更新本文件。用户能感知的条目必须同时出现在 `README.md`「与上游的差异」。原因已有 ADR 的只链接，不重述。逐次同步的摘要和计划仍放 `docs/upstream-sync/`。

## 何时更新

出现下列任一情况即更新本表，不要攒到发布：

- 对照了某个上游标签或提交
- cherry-pick、手工移植、跳过或改写了上游提交
- 本分叉新增、删除或改写了上游也有的能力
- 发布本分叉版本（更新下表本分叉一行，并在 README 与 Release 说明写明同步到的上游版本）

完成标准：表中每一行仍描述**当前**行为；「性质」列不是「完整移植」时，原因列有 ADR 链接或一句现因。

## 同步规则

评估上游功能是否同步时，按这两条判断：

1. 上游功能默认同步，先看实际表现再决定去留；只有像本机路由这样冲突面大、已明确不要的功能除外。
2. 评估是否同步时，改写的行数不算代价。实机验收、长期维护等其他代价照常计算。

## 当前差异

2026-10-03 针对模型能力与排序核对上游 `master` 固定提交 `398f2f0dfb3213cedbef2e77866f49a06d27e5da`。相关第三方能力名单尚未包含 GPT-6.1 Sol，缺少模板时仍回退四档。本次仅做针对性修复，不改变上方整批移植锚点。需求与验收分别见 [#16](https://github.com/IpiggyI/codey/issues/16) 和 [#17](https://github.com/IpiggyI/codey/issues/17)。

2026-10-08 的 Fast 修复在本地 `vendor/CodeyRuntime/crates/codey-runtime-core/src/bridge.rs` 中增加 `Page.enable`，使当前桥接注册的新文档脚本在重载后执行；请求编号增加页面独有标识，防止旧页面完成响应交给新页面回调；公开既有 CDP 连接函数，供服务档位安装入口复用回环地址回退和连接预算。2026-10-12 vendor 更新到 `11de98c6` 时已保留，上游仍未包含；`tests/cdp_bridge.rs` 中的握手编号随之多一条命令。2026-10-18 vendor 更新到上游 `v1.3.0`（`194c2788`）后，上游已公开 `connect_cdp_websocket`，本地差异只剩 `Page.enable` 与页面独有请求编号两处。甲组又从上游 v1.3.1（`6a9fdf20`）带入 `cdp.rs` 的 `browser_websocket_url`，并为它加了一个本地测试。审计第 4 项又在 `assets/model-catalog-metadata.json` 补入 `gpt-6.1-sol`、`gpt-6-sol`、`gpt-6-luna` 三个模型的元数据，上游没有这三项。2026-10-26 vendor 整目录替换到上游 `v1.3.8`（`530796a2`），上游已自带 `Page.enable`；本地差异剩页面独有请求编号、`browser_websocket_url` 的本地测试和三个模型的元数据，均已保留。下次更新 vendor 时仍须保留或确认上游已覆盖这些差异。原因与验证见 [Fast 修复交接](../handoffs/2026-10-08-fast-service-tier.md)。
