# 本分叉与上游的当前差异

对照上游、挑选、跳过或改写上游提交时，在同一次改动内更新本文件。用户能感知的条目必须同时出现在 `README.md`「与上游的差异」。原因已有 ADR 的只链接，不重述。逐次同步的摘要和计划仍放 `docs/upstream-sync/`。

## 何时更新

出现下列任一情况即更新本表，不要攒到发布：

- 对照了某个上游标签或提交
- cherry-pick、手工移植、跳过或改写了上游提交
- 本分叉新增、删除或改写了上游也有的能力
- 发布本分叉版本（更新下表本分叉一行，并在 README 与 Release 说明写明同步到的上游版本）

完成标准：表中每一行仍描述**当前**行为；「性质」列不是「完整移植」时，原因列有 ADR 链接或一句现因。

## 当前差异

| 区域 | 本分叉 | 上游 | 性质 | 原因 | 用户可感知 |
|---|---|---|---|---|---|
| 请求去向 | Codex 直连用户配置里的 provider | 本机代理 `codey_router` 接管，控制台可增删「线路」 | 二开 | [ADR 0001](../adr/0001-remove-built-in-router.md) | 是 |
| 用户配置 | 只读，不写 `config.toml` | 会写入路由恢复桩等 | 二开 | [ADR 0002](../adr/0002-user-config-is-read-only.md) | 是 |
| 跟踪方式 | 按提交挑选；vendor 整目录替换 | 上游主线 | 二开 | [ADR 0003](../adr/0003-track-upstream-by-cherry-pick.md) | 否 |
| 客户端更新 | 不检查、不下载、无入口 | 检查并安装；有预发布脚本 | 二开 | [ADR 0003](../adr/0003-track-upstream-by-cherry-pick.md) 后果 | 是 |
| 同一会话换 provider | 没有；需新开会话，历史 `codey_router` 会话走显式迁移 | 跨线路换模型，并归一化历史 | 二开 | [ADR 0001](../adr/0001-remove-built-in-router.md) | 是 |
| 请求日志 | 无界面；打开命令返回已移除 | 系统浏览器独立页：筛选、耗时、用量、清理 | 二开 | 记录入口在本机代理里，随路由删除 | 是 |
| 周限额度估算 | 没有从请求记录反推美元周限 | 请求日志页「周限额度估算」 | 二开 | 依赖官方账号请求日志，本分叉不记对话请求 | 是 |
| 账号额度 / 对话用量 | 账号额度在侧栏底部；输入栏芯片只显示对话用量和缓存倒计时 | 侧栏额度 + 日志估算 | 部分移植 | 侧栏额度按上游 c064261 收回；日志估算依赖请求日志，不收 | 是 |
| 额度用尽后仍可发送 | 控制台开关，默认开，关闭后需重启 | 本机代理启用时才注入 | 改写 | 本分叉没有本机代理，见 [ADR 0001](../adr/0001-remove-built-in-router.md) | 是 |
| 模型名称 GPT- 前缀 | Codey 启动时强制保留 | 跟随官方开关，可能被去掉 | 二开 | 官方开关 `3849065407` 为假时前端删前缀，见 `INTERNAL_DEVELOPMENT.md` | 是 |
| 控制台 provider | 只读当前项 | 可新增、编辑、删除线路 | 二开 | [ADR 0001](../adr/0001-remove-built-in-router.md) | 是 |
| 宠物窗口拖拽恢复 | 没有 | overlay recovery | 跳过 | 依赖已删除的 overlay 原生恢复 | 是 |
| 发往服务的内部头 | 无本机代理转发层，对话不经 `x-codey-*` | 代理剥内部头后再发上游 | 不适用 | 没有对应路径，不是漏移植 | 否 |
| 主进程补丁 | `--require` 优先，Inspector 回退，CLI 不能冒充；控制台展示注入路径 | 同左 | 完整移植 | 2026-09-15 补上控制台「主进程注入」；后端此前已在 | 是（路径徽章） |
| 入口开关 | 只读检测；未知入口停用，关闭入口不改写 | 上游另保留历史修复资产恢复入口 | 改写 | 不写官方二进制；关闭增强入口时尝试兼容启动并显示原因 | 是 |
| 上游 1.0.1 路由修补 | 不收 | 跨线路历史、嵌套跨线路拒绝、内部头外发约束 | 跳过 | 纯路由，见 ADR 0001 | 否（本分叉无该面） |

「用户可感知 = 是」的行必须能在 README 找到对应句子。注入路径徽章写在控制台，README 不写 `--require` / Inspector。

## 半移植检查

挑选上游提交后，核对这些是否一起落地：

- 后端字段是否有对应控制台文案（本次漏过的就是 `startupInjectionMode`）
- 用户可见能力是否写入 README「与上游的差异」或功能条
- 维护者路径是否写入 `INTERNAL_DEVELOPMENT.md`（当前结构，不是版本流水账）
- 测试是否仍按「已删除的上游 UI」或「故意不展示」断言；若产品决定改了，测试标题和断言一起改
