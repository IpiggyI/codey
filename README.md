# Codey

本仓库是 [SuperGness/codey](https://github.com/SuperGness/codey) 的修改版。当前产品版本 1.4.2。版本号由本分叉独立维护。这一版已与上游 [v1.5.1](https://github.com/SuperGness/codey/releases/tag/v1.5.1) 同步，按需纳入上游的改动；与上游的差异见下方「与上游的差异」。

Codey 是 Codex 桌面客户端的增强启动器。它会启动 Codex，并在 Codex 页面内提供统一控制台，用于切换渠道，管理模型清单、官方账号、MCP 与 Skill，以及使用任务辅助能力、通知和诊断。请求发往哪里，由你自己写的用户配置和你在控制台选择的渠道决定；Codey 不代理、不转发请求。

设置有未保存的更改时，标题栏会出现「放弃更改」，确认后恢复到上次保存的设置，控制台保持打开；直接关闭前也会要求确认放弃。保存进行期间继续做的修改不会丢失，保存完成后仍作为未保存的更改保留。侧栏帮助按钮缺失时，Codey 入口会跟随个人资料按钮；侧栏重建期间会等待恢复。

## 与上游的差异

- 请求由 Codex 按你的用户配置直接发往所选渠道对应的 provider，本分叉不接管请求去向。上游有内置的本机代理，本分叉没有。
- 控制台列出渠道：你的用户配置里的每个 provider，加上官方账号。你可以切换当前渠道，并为各渠道设置默认模型，但不能在控制台新增、编辑或删除 provider。Codey 在启动、重启和退出时不改写你的用户配置；只有你在控制台明确执行的操作才会写 Codex 的配置或登录文件，包括修复插件市场、修复 Codex 配置、管理 MCP 与 Skill、切换官方账号，写入前都会先备份。
- 每个会话只能在创建它的渠道上继续。切换到别的渠道后，打开其他渠道的会话时，Codex 会提示「继续聊天未成功」，这个会话不能继续对话；要继续，请切回它的渠道。新会话使用当前渠道。各官方账号在这一点上算同一个渠道。上游可以在同一会话内切换请求去向。
- 控制台是左侧分组导航的多页布局：基础功能、provider 与模型、提示词优化、子代理优化，以及「扩展生态」下的 MCP 管理和 Skill 管理；切换页面时保留未保存的草稿。没有内置路由管理页，也没有 Codey 插件页。
- 可以保存多个官方账号，每个官方账号是一个渠道，切换账号会改写 Codex 的登录。Codex 正在运行时，切换前先请你确认重启，确认后立即切换并重启 Codex；Codex 未运行时直接切换，下次启动生效。上游为每个账号单独设置请求去向，并提供官方直连（Sign in with ChatGPT），本分叉都没有。
- 浏览器登录添加官方账号时，如果登录无法自动完成，登录对话框仍会显示登录链接，你可以把浏览器最终停留的地址粘贴回对话框完成添加。上游遇到这种情况会直接中止登录并报错。
- MCP 与 Skill 管理在写入或删除前，会把原内容备份到 Codey 自己的数据目录。上游的扩展管理还含 Codey 插件、插件包导入以及日志查看与清理，本分叉没有。
- Codex 启动代理只作用于 Codex 客户端和命令行；上游另外为原生插件的共享服务设置代理，本分叉没有这部分。
- 不检查、不下载、不安装客户端更新，界面上没有更新入口；安装包只通过 GitHub Release 提供。
- 没有请求日志界面。
- 桌面操作插件需要手动准备，安装和启停由 Codex 管理。准备不会修改你的 Codex 设置；既有插件市场的手动修复会更新插件来源设置。
- 账号额度显示在 Codex 侧栏底部。对话用量显示在输入框下方的统计条，输入栏没有用量芯片。账号额度用尽后继续发送由控制台开关控制，默认开启；本分叉没有本机代理，不靠代理放开发送。
- 统计条不显示首个 Token 等待时间，上游显示。缓存剩余时间在「会话」卡片里以文字倒计时显示，条上没有。卡片展开时带短暂的淡入上浮动画，系统开启「减少动态效果」时没有动画。上游把统计条改版为首个 Token 等待、模型与工具用时拆分等指标，这些指标来自上游内置路由的请求日志，本分叉没有这份数据，所以不采用改版；统计条保留原有的三个按钮和三张卡片。
- 通过 Codey 打开 Codex 时，模型名称会保留官方客户端可能隐藏的 GPT- 前缀。
- 控制台标题栏有「系统设置与偏好」对话框，显示 Codey 版本、Codex 版本和 Codex 目录，可复制目录路径，并提供「修复 Codex 配置」。上游对话框里的设备号和更新策略，本分叉没有；配置修复前的备份放在 Codey 自己的数据目录，上游放在 Codex 目录下。
- 页面增强随 Codex 打开一并生效，默认中文界面保留，不需要刷新页面；新开的 Codex 窗口同样带上这些增强。个别增强项无法适配当前 Codex 版本时只跳过这一项，其余照常工作。增强来不及赶上页面加载时，Codey 不会强行重载页面，该窗口的部分增强可能不生效，重启 Codex 后恢复。
- 第三方模型清单默认参考可用的官方顺序；同步弹窗和统一模型目录卡片都支持拖动排序、保存和取消。手动排序会在再次同步后保留，也可恢复官方排序。官方顺序暂不可用时保留已有顺序。首次进入设置时，未保存过手动排序的旧清单也会应用官方顺序。
- GPT-6.1 Sol 在第三方服务下可选择完整六档思考强度，包括 `max` 和 `ultra`；实际可用性仍由服务商决定。
- 第三方服务下，GPT-6-Astra、GPT-6-Sol、GPT-6-Luna、GPT-5.6-Sol、GPT-5.6-Terra 和 GPT-5.6-Luna 在模型选择器里都可以选到 `ultra`，不受官方开关影响；其他模型的思考强度保持原样。
- 指定轮次删除：删除最后几轮时使用 Codex 自带的撤回，立即生效；删除中间的轮次会先请你确认，确认后重启 Codex。Codex 把会话管理放在桌面宿主进程时（当前版本的 Codex 就是这样），页面读不到轮次顺序，每一次删除，包括最后几轮，都先请你确认并重启 Codex。上游是直接改写对话记录，在宿主进程模式下改写后重新载入对话，不重启 Codex。
- Fast 档位：官方 ChatGPT 账号明确不允许使用 Fast 时，本分叉保持它不可用；上游在这种情况下仍会显示 Fast。
- 子代理沿用上游的三种角色（检索、开发、复核）：各角色的工具权限相同，检索只读、复核不改源码的边界只由提示词引导，同时最多 2 个子代理；有子代理在工作时，主代理的可用工具由活动子代理的角色决定。与上游不同的是，本分叉在派生前检查角色绑定的模型是否在当前渠道的模型目录中，不在时拒绝派生并提示重新选择；上游靠内置路由映射模型，不做这项检查。
- 侧栏额度的悬停详情会按名称列出账号的其他额度组，上游只显示通用额度。
- 提示词优化获取模型列表时不需要先选好模型，三种来源都是；选官方账号（或沿用的当前 provider 使用官方账号登录）时，列出的是本机可见的官方模型，不联网获取。上游没有官方账号和沿用当前 provider 这两种来源，只有手动配置，手动配置下同样不需要先选模型。
- 控制台标题栏没有扫码入群的二维码入口，只保留 GitHub 仓库按钮；上游有。
- 设置有未保存的更改时，标题栏多一个「放弃更改」，可以不关闭控制台就恢复到上次保存的设置；上游只能在关闭时选择放弃更改。
- 当前 Codex 版本改动导致个别页面增强不再适用时，控制台「系统优化」会显示「页面资源补丁」异常并列出受影响的增强名称；上游没有这个提示。
- 子代理优化页有只读的「运行方式」，按开关和角色分组展示 Codey 启动 Codex 时为子代理写入哪些文件、改用哪些设置、注入哪些规则，以及这些内容现在是否生效；内容就是内置定义，每次启动都会按它重写，磁盘上的手工修改不保留；上游没有这个页面。
- 模型同步和提示词优化可以使用 Codex 同样支持的两种密钥来源：配置的命令取得的密钥，以及 API 密钥登录保存的密钥。上游没有命令取得密钥的方式。
- 渠道不走 OpenAI 鉴权时（例如中转渠道），Codex 的项目列表和置顶会话不再丢失，也不会重新出现新手引导；上游在这种情况下项目列表会变空。
- Windows 上，Codey 启动时会删除超过 7 天没有用过的 Codex 旧运行副本，释放磁盘空间；正在使用的副本不会被删除。上游没有这项清理。

## 主要功能

- 启动与状态：自动启动或重启 Codex；Windows 遇到暂时性启动错误时会自动重试一次，并跟随商店安装位置的变化。集成失败后，只有确认清理与临时状态恢复成功，才会尝试打开原生 Codex。展示运行状态和功能生效情况，并按实际检测结果提示正常、待确认、需检查或异常。当前 Codex 版本改动后，个别页面增强可能不再适用：控制台「系统优化」会显示「页面资源补丁」异常，并列出受影响增强的名称。Codey 版本、Codex 版本和 Codex 目录在标题栏的「系统设置与偏好」对话框中查看：Codex 未运行时版本显示「未运行 / 未检测到」，读取失败时显示原因，目录路径可一键复制并提示复制结果。
- 渠道、provider 与模型：控制台的 provider 页面列出全部渠道，即你的用户配置里的每个 provider，加上官方账号。可以切换当前渠道，并为每个渠道设置默认模型；切换时使用的模型依次取渠道自己的默认模型、全局默认模型和 Codex 配置里的模型，渠道行会写明用的是哪一个；三处都没有时，先填写模型再保存并切换。设置默认模型时，每个渠道都可从自己的模型清单里选择；清单为空时输入框下方会提示，仍可直接输入模型名称。Codex 正在运行时，切换渠道前先请你确认重启，确认框会提醒正在执行的本地任务将被中断；确认后立即切换并重启 Codex，取消则什么都不改。Codex 未运行时直接切换，下次启动生效。切换不会改写你的用户配置。没选过渠道时，行为和原来一样，跟随用户配置的默认 provider。所选渠道已从用户配置中删除或不可用时，Codey 回退到用户配置的默认 provider 并显示提示。模型清单同步、提示词优化、当前 provider 显示和子代理角色模型都跟随当前渠道。每个会话只能在创建它的渠道上继续：切换到别的渠道后，打开其他渠道的会话时，Codex 会提示「继续聊天未成功」，这个会话不能继续对话，要继续请切回它的渠道；新会话使用当前渠道；各官方账号在这一点上算同一个渠道。控制台只读展示当前 provider（标识、地址、接口格式、是否官方账号鉴权），不能新增、编辑或删除 provider。模型清单按当前 provider 同步，换用另一套配置模板后不会把上一套地址的模型清单带到新地址。仍支持模型同步、手动维护和全局默认模型。空的模型目录不会交给 Codex。模型选择器在更多模型上仍提供 Fast 与思考强度，Fast 在当前版本的 Codex 上可用；模型目录声明了 Ultrafast 的模型，选择器里会显示 Ultrafast 档位。官方 ChatGPT 账号明确不允许 Fast 时，该档位保持不可用。用 Codey 打开时，模型选择器里的名称会保留 GPT- 前缀。保存后这些选项会在之后打开模型选择器时更新；若仍未变化，按界面提示重启。用户配置无法解析时会明确报错并拒绝启动。官方和第三方模型都可配置上下文窗口、自动压缩阈值和输出预留，兼容原有 1M 设置；控制台显示的上下文预算与 Codex 实际生效的一致，模型目录覆盖后仍保留必需的模型和每个模型的预算，第三方模型不会沿用官方模型的压缩兼容标识。自动查找 Codex 安装时会跳过已不存在的安装。保存设置后，应用情况在后台依次进行，界面显示正在应用、已应用、需重启或失败及原因；连续保存以较新的一次为准，较早的结果不会覆盖较新的状态，应用成功后状态提示自动消失。不需要重启就能生效的改动不再提示重启：应用尚未结束、模型清单稍后刷新，或即时应用暂时失败时，界面按实际情况显示正在应用或失败，失败后可以重新应用；启动相关的设置、子代理优化总开关、防御性编程控制开关、上下文预算和模型能力的改变仍会提示重启。模型目录与预算不兼容时，可以确认恢复默认预算后重试；原始模型目录保持不变。模型同步会校验已打开的选择器，失败时恢复原列表。模型同步和提示词优化使用 Codex 为当前 provider 配置的同一把密钥，包括通过配置的命令获取的密钥和 API 密钥登录的密钥；Codey 不会保存这把密钥，也不会写回你的配置。
- 账号额度：本机有可用 ChatGPT 登录（含旧版登录态）并开启额度显示时，在 Codex 侧栏底部展示套餐窗口的剩余百分比、进度和重置时间，并标出套餐名称；Pro 套餐按档位显示为 Pro 100、Pro 200、Pro 500，三档配色不同，无法识别的套餐名按原样显示。卡片只有周额度一个窗口时，用沿卡片边框的进度环显示剩余比例，重置时间写成日期加时刻。悬停或用键盘聚焦可查看各窗口的剩余百分比、进度和重置时间，以及 Credits 余额；Credits 余额为 0 时不显示这一行。悬停详情还会列出官方账号的剩余重置次数和最近一个重置次数的过期时间；拿不到过期时间时只显示次数，拿不到次数或次数为 0 时不显示这一项，侧栏底部摘要不显示重置次数。最近一个重置次数在 18 小时内过期时，这一项变红并带闪烁的提示点，侧栏底部摘要上也会出现一个红点。账号另有其他额度组时，悬停详情会按名称单独列出，并标明已用尽的额度组；侧栏底部摘要只显示通用额度。额度跟随官方账号，不看当前所选模型或 provider。没有 ChatGPT 登录时不显示额度。若当前服务是多人共用账号池，数字不一定代表本人消耗。刷新失败时会继续使用本周上次成功获取的数据；暂时更新失败时保留上次结果。只有指向 ChatGPT 官方 Codex 服务时，控制台才把该 provider 标为官方账号鉴权。
- 额度用尽后仍可发送：默认开启。开关打开时，Codex 自己的额度用尽警告和锁定提示会被隐藏，输入框和发送保持可用，便于改用 API 登录继续对话。若仍用已经用尽的官方账号发送，请求会失败，并显示服务返回的限额错误。在控制台关闭后需要重启 Codex。Codex 自己的「Codex 和 Work 额度用尽」提示和团队版的额度提示右上角带有关闭按钮，不依赖此开关；点击后隐藏这条提示。隐藏不会保存，重新载入页面或 Codex 重新生成这条提示后，提示会再次出现。
- 对话用量：输入框下方有一条统计条，三个按钮各对应一张详情卡片。第一个按钮显示轮数、步数和本轮平均速度，卡片「最近一轮统计」依次列出模型用时、工具调用用时、最近一次用时、本轮平均速度、最近一次速度和本轮推理。第二个按钮显示会话累计 Token 和缓存命中率，卡片「Token 用量」依次列出会话缓存命中、最近一次缓存命中，会话累计的新增输入、缓存读取和输出，以及最近一次请求的新增输入和输出；新增输入是没有命中缓存的那部分输入；Token 数用 1.8M 这样的简写，鼠标悬停可看到精确值。第三个按钮显示费用估算和上下文占用，卡片「会话」依次列出账号、开始时间、上次回复、上下文占用、缓存剩余时间、压缩次数和会话费用估算。悬停或用键盘聚焦按钮可预览卡片，离开后自动收起；点击按钮固定卡片，点击外部或按 Esc 关闭。卡片展开带短暂的淡入上浮动画，系统开启「减少动态效果」时没有动画。账号在走官方账号登录时显示登录邮箱，否则显示 provider 名称。打开已有用量的历史对话也会直接显示，无需再次发送消息，切换对话时统计条立即换成新对话的数据。这是这次对话发生了什么，不是账号套餐还剩多少。读不到的项显示「—」；没有费用数据时不显示费用，第三个按钮只显示上下文占用；首个 Token 等待时间拿不到，不显示。生成过程中显示「生成中」，不显示速度估算，这次请求完成后才显示速度和用量。缓存剩余时间从这条对话最近一次模型请求起算，不论这次请求是在哪个窗口发出的；刷新或重启 Codex 后也会接着算。未过期时显示分秒倒计时，绿色表示还早，黄色表示快过期，红色表示马上过期；过期后显示「已过期」，读不到这条对话的请求记录时显示「未知」。只切换模型、思考强度或 provider 而没发消息时，计时不变。有效时间默认 30 分钟，可在控制台按 1 到 180 分钟调整。这是本机估计，不是服务商返回的到期时刻。
- 官方账号：可以保存多个 ChatGPT 官方账号。添加方式有四种：在浏览器中登录、导入 Codex 当前的登录、粘贴刷新令牌或 OAuth JSON、选择 Codey 导出的账号文件导入；格式不对、文件不符合要求或浏览器登录无法完成时，会说明原因。每个账号可以导出为账号文件，用于备份或在另一台设备导入；导出不会刷新令牌，文件含登录凭据，需要妥善保管。浏览器登录不能自动完成时（例如登录所需的端口被其他程序占用），登录窗口始终显示登录链接，你在浏览器里完成授权后，把浏览器最后打开的地址粘贴回窗口，就能继续添加账号。每个账号单独显示账号额度和套餐标签，可以移除，移除前会确认；移除账号不会退出 Codex 当前的登录，也不会自动切换到别的账号。每个官方账号也是一个渠道，可以和 provider 一起切换。Codex 正在运行时，切换账号前会请你确认重启；确认后 Codey 先备份当前登录，再把 Codex 的登录改写为该账号，并直接重启 Codex，取消则什么都不改。Codex 未运行时直接切换，下次启动生效。账号的渠道没有默认模型、全局默认模型和 Codex 配置里的模型也都为空时不能切换，界面会提示你先在渠道列表为该账号设置默认模型。在某个账号下开始的对话，切换账号后可能无法继续；界面会提示，遇到时请新开对话。Codex 不把登录保存在文件里时，切换账号和导入当前登录都不可用，界面会说明原因。保存好的令牌不会再显示在界面上，也不会写入日志；粘贴凭据的输入框会显示你自己输入的内容。
- MCP 与 Skill 管理：控制台侧栏「扩展生态」下有 MCP 管理和 Skill 管理两页。MCP 可按当前用户或某个项目的范围新增、编辑、启停和移除，支持粘贴或导入 JSON 配置，并可测试连接；测试会执行配置的启动命令或连接远程地址，请只对信任的服务使用。MCP 保存后会自动通知 Codex 重新读取配置，未能确认时会提示重启 Codex。Skill 分用户、项目和系统三个范围，可从本地目录或 ZIP 预览后安装，安装后默认禁用；可查看、启停、导出和删除，系统内置的 Skill 只能查看；Skill 变更后请在新会话中确认。每次写入或删除前，Codey 会把原内容备份到自己的数据目录，备份失败则不写入；写入后校验失败时，界面会给出备份位置。
- Codex 配置修复：「系统设置与偏好」对话框的「修复 Codex 配置」会先请你确认，确认后检查并修复，没有可修复的问题时会告知。可以修复的情况有：Codex 配置目录或配置文件缺失，以及早期版本写入的 Codey 模型目录配置项。配置文件格式错误、provider 引用缺失等属于你自己的内容，只报告位置，不改写。修复前原文件会备份到 Codey 自己的数据目录，修复后会校验，校验失败时提示备份位置；修复成功后请从 Codey 重启 Codex。启动、重启和退出时不会自动修复。
- Codex 启动代理：控制台可以设置 Codex 使用的网络代理，默认为空，即 Codey 启动 Codex 时不修改代理设置，环境和启动参数保持原样。保存时会检查地址格式，带用户名和密码的地址也可以使用。设置后 Codex 客户端和命令行都经此代理访问网络，代理地址保存后需重启 Codex 才生效；启动前会检查代理能否连通，连不通时不启动 Codex，并说明原因。带用户名和密码的代理地址会保存在 Codey 的设置里；Codey 会在本机替 Codex 向代理认证，认证期间本机其他程序也能免凭据使用这个代理。
- 会话增强：优化任务时间和运行状态展示，任务已结束而界面仍显示进行中时会与 Codex 核对并更正，支持会话导入、导出、整段或指定轮次删除；删除后不能在会话列表里撤销。Codex 和 Work 模式均提供会话悬停快捷按钮：置顶、导出、归档和删除。Work 的其他操作可通过右键菜单使用；用键盘聚焦时也会显示菜单按钮。当前任务结束后才能删除轮次。删除最后几轮会立即生效并局部更新当前对话；删除中间的轮次会先请你确认，确认后 Codex 会重启，且此 Codex 窗口中有任何任务在运行时不能删除。Codex 把会话管理放在桌面宿主进程时（当前版本的 Codex 就是这样），消息删除同样可用，但每次删除都按中间轮次处理：先请你确认，确认后重启 Codex，已删除的轮次会立即从画面中隐藏。缓存会话和其他窗口不会被误选。启动时不会改写历史会话的归属。若有历史会话仍指向已移除的本机代理，控制台会提供迁移入口，确认后先备份再改写到你指定的 provider，过程中会暂时重启 Codex。页面状态异常时会尝试重新同步。
- 插件与页面增强：修复插件市场和本地插件展示，提供可离线恢复的精选插件内容，并改善常用会话操作和页面体验。结账和价格页面不再在后台预加载，打开时才加载。可显式准备桌面操作插件；准备后重启 Codex，再到插件页安装或更新，启用和停用也在插件页操作。Windows 和 macOS 支持此插件，Linux 暂不支持。
- 提示词优化：可使用官方账号、当前 provider 或独立填写的连接信息，一键优化输入框中的提示词；可改优化指令、获取模型列表并测试连通。写回的是最终提示词，不含推理过程，结果仍可继续编辑。
- 子代理角色：提供检索、开发、复核三种角色，可分别选择模型与思考强度，各角色的工具权限相同；同时最多 2 个子代理。子代理优化页有只读的「运行方式」，按「Codey 子代理角色与调度增强」开关、各个角色、「防御性编程控制」开关和门禁四组排列：每项写明由哪个开关或角色触发，内容写入哪个文件、在本次启动时改用哪项设置或在什么时机注入，并可展开查看完整内容。角色名称与上方角色列表一致；未启用的角色也列出启用后会写入的内容，并标明尚未生效。内容按已保存的设置显示，页面上有未保存的修改时会标出，保存后自动刷新；两个开关在保存并重启 Codex 后生效；角色启停、模型和思考强度保存后从下一次派生起生效，正在运行的子代理沿用原配置。显示的思考强度是保存的值，启动时可能按模型目录调整。这里只能查看，不能修改。默认只在宽范围、可并行或需要专门证据时才派生子代理，不是强制分工。只有检索子代理在工作时，主任务可以继续独立的写入和命令；有其他角色的子代理在工作时，主任务只能使用协作工具和读取文件、查看本地文件、搜索、按名称查找文件、查看图片这五项只读工具。打开子代理详情后，标题右侧显示该任务使用的模型短名与思考强度。正常任务不会仅因运行时间长、状态未变化或没有新消息而被回收。角色绑定的模型不在当前清单时会明确标出待重选，不会悄悄换成别的模型，重新选择前不会派生该角色。运行配置异常时会暂停新任务并提示恢复方法。
- 防御性编程控制：控制台有「防御性编程控制」开关，默认关闭。开启后，Codey 为新会话、压缩后的会话和子代理加入适度原则，减少不必要的兼容层、兜底代码和重复检查。已有会话在下次压缩后才会获得这些规则，恢复的旧会话沿用它原有的内容。这些规则是提示，不是强制检查，更具体的指令可以覆盖它。改变开关后需要重启 Codex 才生效。
- FastCtx：可选启用内置 FastCtx，提升长任务中的文件读取、搜索、发现和批量替换体验；检测到已有 FastCtx 配置时不会重复加载。
- 消息通知：支持飞书、企业微信、Telegram、微信 ClawBot 和 ntfy。已配置的通知渠道会同时接收任务完成、失败和等待介入提醒，ntfy 的三类提醒使用不同的标题和标签，失败和等待介入的优先级高于完成。ntfy 需要填写服务器地址和主题，访问令牌可选：地址只接受 HTTPS 根地址，可用公共服务器或自建服务器，主题不填时会提示。保存后的访问令牌不会回显。可用测试发送确认配置。通知先保存在本机，网络恢复后自动重试，重启后继续投递；同一个会话的同一轮只通知一次，一个通知渠道失败不影响其他渠道。送达状态不明的通知不会重发，以免重复打扰，因此个别通知可能收不到。打开 Codey 时已有的历史会话不触发通知。
- 稳定性与存储保护：提供健康检查、会话恢复、可识别的 Windows 客户端崩溃自动恢复、诊断存储统计与清理，并可按平台启用 Trace、Crashpad、宠物精简（只加载当前选中宠物的形象图）、屏蔽完全访问安全提示，以及 Windows 上的 GPU 渲染模式。宠物设置应用失败时仍可继续启动。与 Codex 的连接中断或暂时不可用时，Codey 会持续自动恢复，长时间不可用时降低重试频率；打开设置面板前会先确认连接可用。

## 使用方式

打开 Codey 后，它会自动启动 Codex。进入 Codex，点击左侧图标栏底部带 Codey 图标的按钮即可打开控制台。保存设置后，可立即生效的功能会直接更新；需要重启的项目会在界面中提示。provider 能力不变时，保存模型增删会更新 Codex 模型清单；部分模型能力仍需重启时会单独提示。

## 注意事项

- Codey 只面向 Codex 桌面客户端，不覆盖命令行版本。用 Codey 打开的 Codex 会使用中文界面。
- 启动 Codey 时，如 Codex 已在运行，Codey 可能先关闭并重新启动它；正在运行的任务会被中断。
- 官方账号依赖 Codex 的 ChatGPT 登录状态；第三方 provider 的可用功能取决于对应服务和账号。导出的账号文件含登录凭据，请只放在自己信任的位置，不要分享给他人。
- 官方账号保留 Codex 原版可用的模型，新增官方模型默认可见。你可以在设置中取消勾选，也可以重新勾选恢复。
- 部分增强能力会随 Codex 版本和所选 provider 而变化，请以控制台提示为准。
- 自定义上下文预算修改后重启 Codex 生效；设置更大的数值不会扩大服务端容量。无法识别容量的模型使用保守预算，建议按服务商公布的限制调整。
- 远程压缩是否可用由当前 provider 与模型目录共同决定。已有压缩历史无法用于目标服务时，请先在原 provider 处理后再切换，避免缺失上下文。
- 数据库查询请使用只读账号；子代理的角色边界只由提示词引导，不能替代数据库本身的权限设置。
- 本修改版不会检查、下载或安装客户端更新；安装包只通过 GitHub Release 提供。
- macOS 未签名安装包可能被系统拦截，可在确认来源后按系统提示允许打开。
